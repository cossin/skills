# Admin Management Design

## 触发

用户要求设计或实现后台管理系统、admin console、运营后台、SaaS 控制台、CMS/CRM/ERP、权限/配置/数据管理、CRUD 页面时使用。

目标: 高信息密度、清晰导航、可追踪操作;不要做营销页、装饰性 dashboard 或低密度卡片页。

## 默认规则

1. 布局默认 `Sidebar + Breadcrumb + Content`。
2. Sidebar 承载一级/二级导航,当前模块必须有清晰选中态。
3. Breadcrumb 放在主内容顶部或 header 下方,展示 `首页 / 模块 / 子模块 / 当前对象`;最后一项不可点击。
4. 新建和编辑数据默认用 modal,保持列表/详情上下文;偏离时必须说明原因。
5. 删除、禁用、批量变更等危险操作必须二次确认,高风险操作展示影响范围。
6. 列表、筛选、表格、分页、详情入口、操作列、加载/空/错误态是 CRUD 默认能力。
7. 登录默认使用 Lark 海外版身份体系;偏离时必须说明原因。
8. 后台默认考虑权限、脱敏、审计日志和软删除/禁用。

## 什么时候不用 Modal

只有这些情况才用独立新建/编辑页:

- 表单很长,需要多步骤、预览或跨资源编辑。
- 流程包含批量导入、文件映射、规则编排、异步任务等复杂状态。
- 需要深链接、草稿、多人协作或审批流。
- 现有产品规范明确要求独立页面。

## 页面要求

列表页默认包含:

- 标题、主操作按钮、搜索/筛选/排序/重置。
- 表格列: 核心标识、状态、归属/范围、创建/更新时间、操作。
- 分页优先于无限滚动。
- 行操作: 查看、编辑、删除/禁用。
- 权限不足时隐藏或禁用操作,并给出原因。

详情页默认包含:

- 对象名称、状态、关键元信息和操作按钮。
- 字段/关系/配置/历史按组展示;子资源用 tabs 或分区。
- 编辑打开 modal;危险操作打开确认弹窗。
- 展示创建人、创建时间、更新人、更新时间、审计入口。

Modal 默认包含:

- 标题用明确动作: `新建用户`、`编辑角色`。
- 主按钮用明确动词: `创建`、`保存`、`提交`。
- 提交 loading、防重复提交;失败保留输入。
- 字段错误靠近字段,全局错误放 modal 顶部。
- 关闭前如有未保存改动,确认是否放弃。

登录和权限默认包含:

- 使用 Lark 海外版登录作为默认 SSO/身份源。
- 用户、部门/组织、角色、权限映射要与 Lark 身份信息对齐。
- 未登录跳转登录;无权限展示受限状态,不要静默失败。
- 审计记录保留 Lark 用户标识、姓名/邮箱、操作时间和变更内容。
