# Code Review

## When to use
用户要求做代码审查、检查代码、review PR、审查本次改动时触发。默认审查范围:当前 git diff(未提交 + 已暂存)。用户指定路径时只审查该范围。

## 核查清单

对每一项逐条核对目标代码。发现违反即记录,不要漏项。

### 1. 禁止空实现与占位 mock
- 函数/方法体必须有真实逻辑,不得仅包含 `pass`、`return None`、`return {}`、`return []`、`TODO`、`raise NotImplementedError`、空 `catch {}`
- 禁止返回写死的假数据冒充真实调用(测试 fixture 除外)
- 声明但无调用方的函数视为未完成,应删除或补齐调用方
- 接口方法必须在所有实现类中真正实现,不允许留空实现占位

### 2. 外部 API 对接一致性
- 对照官方文档 / OpenAPI / SDK 类型定义,核对**请求**字段名、类型、必填性、大小写
- 响应解析必须用 `.get()` / 可选链 / 安全解构处理**可选字段**;禁止直接 `obj["x"]` / `obj.x` 假定存在
- 嵌套结构缺失、数组为空、字段为 null、类型为联合类型 → 都要有分支处理
- 枚举值、状态码、错误码必须对齐文档;未文档化的值视为未知不得硬写分支
- HTTP 状态码处理要覆盖非 2xx,不得假定永远成功

### 3. 分页必须完整遍历
- 使用 `while has_next` / 游标 / `next_token` / offset 递增,直到明确终止条件
- 禁止只取首页或固定 N 页(除非业务明确要求 top-N 并在注释中说明)
- 终止条件必须明确且与文档一致:空结果、无 next_cursor、total 达标 等其中之一
- 大数据量使用生成器/流式返回,避免一次性加载到内存
- 注意分页死循环风险:游标未变化、页数无上限时需熔断

### 4. 单元测试覆盖
- 每个新增的公共函数必须有对应测试
- 覆盖三类路径:正常、边界(空输入、最大值、零值)、异常(错误输入、依赖失败)
- 外部依赖(HTTP、DB、时间、随机)可以 mock;核心业务逻辑不得 mock
- 不允许只测 happy path;分支覆盖率要体现在 assert 上
- 测试要能实际跑通,不能只是占位

### 5. 禁止硬编码
- 魔法数字、URL、路径、状态字符串、错误码必须提升为常量或枚举
- 运行时配置(endpoint、超时、key)走环境变量或配置文件
- 同一字面量在代码中重复出现 ≥ 2 处即需常量化
- 优先使用语言原生枚举类型:Python `Enum`、TypeScript `enum` 或字面量联合、Go `iota`、Rust `enum`
- 常量命名要能表达含义,不要 `CONST_1`、`DEFAULT_VALUE` 这类无信息量命名

## 输出格式

必须按下列三段输出,顺序固定:

**Blocking(必须修)**
- `路径:行号` — 违反第 N 条:具体问题 → 建议改法

**Suggestions(建议修)**
- `路径:行号` — 问题 → 改法

**Passed**
- 一句话总结通过的检查项

规则:
- 发现 0 个 Blocking 才视为通过;Blocking 项必须给出具体改法,不能只说"有问题"
- 每条问题定位到具体文件行号,不允许模糊指代
- 未审查的范围要在结尾声明(例如 "未审查 legacy/ 下旧代码")
